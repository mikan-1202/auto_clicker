# Macro Generator / AutoClicker — マウス・キーボード操作の自動化

PythonとTkinterで作成した、Windows向けのデスクトップマクロ編集アプリです。繰り返すクリックやキー入力を操作列として登録し、押下時間・待機間隔・繰り返し回数を設定して保存・再実行できます。

過去に制作したアプリを、現在の知識とAIツールを活用してレビュー・改善しています。設計提案、修正コード、テスト、説明文の作成にはAIの補助を利用しています。

## 主な機能

- 座標指定の左・右クリックと、1文字またはEnter等の特殊キー入力
- 操作ごとの押下時間・待機間隔の設定
- 操作列の繰り返しと、入れ子ループ
- アクションの追加・編集・削除、ドラッグによる並べ替え
- グローバルホットキーによる開始・停止、現在座標のクリック登録
- ホットキーの変更と、JSONプリセットの保存・読込

## 使用技術・処理の構成

Python / Tkinter・ttk / pynput / 標準ライブラリのdataclasses・threading・queue・json・unittest / uv / Ruff。

GUIで編集した操作列を `Action` のリストとして保持し、`MacroController` が検証・コピーして `MacroEngine` に渡します。エンジンは別スレッドで操作を順次実行し、マウス・キーボードへの入力はpynputで行います。

キー監視と実行終了の通知はキューを介して受け取り、Tkのメインスレッドで状態と画面を更新します。

## 技術的に工夫した点

- GUIと実行エンジンを分離し、操作データをdataclassで表現。ループ開始位置と残り回数をスタックに保持して、入れ子の繰り返しを処理する。
- キー監視・実行スレッドからの通知をキューに集約し、Tkのメインスレッドが20ms間隔で処理する。
- 停止要求後も実行スレッドの終了まで再開始を防ぐ。待機は `threading.Event` で中断し、キーやボタンの押下後は `finally` で解放を試みる。
- 実行前に操作列をコピーし、編集用データと実行用データを分ける。
- JSONは値・ループの対応・ホットキーとの重複を検証してから画面へ反映する。保存は同一ディレクトリの一時ファイルを置換する方式とし、置換に失敗した場合は既存ファイルを残す。

操作データとループ処理は元の設計を活かし、レビューではスレッド間通知、停止・再実行の状態管理、JSON入出力を見直しました。

## プロジェクト構成

| パス | 内容 |
| --- | --- |
| `main.py` | 起動入口、Windowsアイコン設定 |
| `auto_clicker/core/actions.py` | 操作データ・値の検証・入力実行 |
| `auto_clicker/core/engine.py` | 別スレッドでの実行・ループ・停止 |
| `auto_clicker/core/controller.py` | イベントキュー・ホットキー・実行状態の管理 |
| `auto_clicker/core/presets.py`・`settings.py` | プリセットの検証・入出力、ホットキー設定 |
| `auto_clicker/gui/` | メイン画面、操作編集、設定画面、独自ウィジェット |
| `auto_clicker/utils.py` | JSON入出力、キー表現の変換 |
| `examples/` | サンプル設定・プリセット |
| `tests/` | 実入力をモック化した回帰テスト |
| `pyproject.toml`・`uv.lock` | 依存関係・開発ツールの設定 |

操作の種類や入力処理は `actions.py`、実行順序や停止処理は `engine.py`、画面の変更は `gui/` を中心に確認する構成です。

## 起動・テスト

Windows、Python 3.12以上（Tkinterを含む）、uvを用意し、リポジトリのフォルダで実行します。

```powershell
uv sync --locked
uv run --locked python main.py
```

アプリ終了後、次のコマンドでテストを実行できます。

```powershell
uv run --locked python -B -m unittest discover -s tests -v
```

テストでは入力送信をモック化し、次の処理を確認します。GUIテストにはTkが動くデスクトップ環境が必要です。

- 入れ子ループの実行順序、待機中の停止、自然終了後の再実行
- 停止処理中の再開始防止、キー・ボタンの解放、実行データのコピー
- JSONの検証、保存失敗時の既存ファイル保持、不正な設定の読込
- プリセット読込失敗時の画面状態保持、アクション編集・削除・並べ替え

実際のアプリへの入力や、画面解像度・DPIの違いによる挙動は、このテストの対象外です。

## 補足

- 開始・停止はホットキーで行います。既定値は開始がF1、停止がF2で、現在の割り当ては画面左側に表示します。
- 入力はその時点のデスクトップやフォーカス先へ送られます。動作確認では入力先と停止キーを確認してください。座標は画面配置に依存します。
- 標準では単独キーを順次入力します。複数キーの同時押しや画面認識は実装していません。
- ホットキー設定は `config.json`、プリセットの既定保存先は `presets/` です。サンプルは [examples/](examples/) にあります。
- 不正なプリセットは画面へ反映せず、壊れたホットキー設定は上書きせずに警告して既定値で起動します。
